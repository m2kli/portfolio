关卡工作台 · AI 设计指南

给任何 AI / 智能体：读完这一页，你就知道工作台怎么读你的地图、怎么判定“合格”，以及怎样设计出一张能直接进工作台、经得起关卡评审的地图。 字段的逐项定义在后面的《AI 关卡设计输出规范》；本页讲怎么用、怎么做好。

0. 你的任务（产出合同）

  • 只输出一份 JSON：不要解释、不要 Markdown 代码块、不要前后缀、不要注释或尾逗号。
  • 格式是 AI_MAP_SPEC v1（"schemaVersion": 1）。
  • 合格 = 同时满足： 1. 结构校验 0 错误（错误会让工作台直接拒绝导入）； 2. 0 告警（告警能导入，但说明设计有问题：门太窄、路线擦墙、门没在墙上……）； 3. 通过本页第 8 节的设计质量清单（校验器查不出来的东西，比如节奏、职责、引导）。
  • 你写的 JSON 是唯一真相：工作台不会替你补数据、不会自动修坐标；你没写的东西就不存在。

1. 工作台怎么运作

工作台是一个只读的静态网页：读入地图 JSON → 校验 → 画成 2D 平面图、3D 块面和压力曲线。它不写回任何文件，也不连接游戏引擎。

你的 JSON ──► 校验（页面与 tools/validate_ai_map.py 同一套规则）
                │ 有错误 → 拒绝导入，提示第一条
                ▼
           2D 平面（SVG）   3D 块面（three.js）   压力节奏曲线   详情面板

你写的每类数据在哪里被看到：

floors[] 楼层页签、竖向分层面板 每层楼板的标高 单看某层时其他层淡显
rooms[] 彩色多边形 + 名称（code + short） 楼板 + 沿房间边自动生成的墙 压力曲线背景色带、详情

routes[] 带箭头的折线；“通行宽度”图层画玩家宽度 地面路带，[x,z,y] 点会爬坡 主线决定压力曲线

2. 坐标、单位与尺度

  • 单位：米。 平面坐标 [x, z]：x 越大越靠东（图上向右），z 越大越靠北（图上向上）。
  • 标高不写在点里，而是来自 floors[].elevation；只有路线的点可以写第三个值 [x, z, y]（绝对标高）。
  • meta.bounds 是整张图的外框，所有点都必须在框内（含边上）。建议外框比房间整体大 1–2 m。
  • 用整数或 0.5 m 网格画房间与门，相邻房间才好严丝合缝；不要写 13.333 这类数。
  • 玩家尺度在 meta.player（一般 radius 0.35、height 1.7）。下表是推荐尺寸，用玩家直径 D = 2×radius 换算：
元素 硬下限（校验器） 推荐
门宽 width ≥ D（否则告警） 普通 1.6–2 m，主线/带怪通过 2–4 m
走廊宽 — ≥ 3 m；主战斗走廊 4–6 m
路线离阻挡物件 ≥ radius（否则告警） ≥ 1 m，主线 ≥ 1.5 m
敌人离墙 在房间内即可 ≥ 1 m
战斗房间 — 短边 ≥ 8 m；Boss 房 ≥ 12×12 m
层高 height > 0 3–4.5 m

3. 设计流程（按这个顺序写）

  1. 先定意图：一句话概念、目标时长/主线长度、几场战斗、一个高潮。写进 meta.subtitle 和 meta.designNotes。
  2. 楼层：floors[] 按 elevation 从低到高排列。单层图只写一个 1F。
  3. 房间网格：先在纸面上用矩形排布。相邻房间共用边界时，两边的坐标必须完全相同（这样门能落在边上，3D 墙会合并成一段）。同层房间不要重叠（外框重叠也会告警，L 形房间请拆成两个矩形房间）。
  4. 门：每扇门是一条落在房间边上的线段，两个点都在那条边上；width 等于线段长度。房间之间要连通，就一定要有门。
  5. 主线（kind:"main"，只要一条）：从入口房间里出发，每次换房间都穿过门的中点附近，最后停在终点房间里。折线点按行进顺序。避开 solid 物件至少 1 m。
  6. 敌人：每个敌人的 center 在它的 roomId 多边形内（同层），离墙 ≥ 1 m；主线上的写 branch:"main"，支线上的写 "optional"。
  7. 物件：掩体、展台、柱子等。会挡路的写 solid:true，并给 height（米）；不会挡路的写 solid:false。
  8. 可选路线（optional / secret / exit）：从主线分叉，给回报（资源、精英、捷径）。
  9. 多层时：加 stairs[]（写 bottom），跨层路线的点写成 [x, z, y]。
  10. 自检：按第 7、8 节逐条过；能跑命令时运行校验器。

4. 节奏：工作台怎么算压力

工作台沿主线（若有 exit 路线则接在主线后面）每 1 m 取一个采样点，计算：

压力(采样点) = Σ  权重(敌人) × exp(−距离 / 5.5 m)      只算 branch:"main" 的敌人
权重：meta.pacing.weights[enemyType]，缺省按 tier：normal 1 / elite 3 / boss 6
休息段：压力 < 峰值 × 20% 且连续 ≥ 4 m

注意：距离只看平面（不分楼层）；optional 敌人不计入。所以敌人放在哪、离主线多远，直接决定曲线形状。

好的曲线是锯齿上升：

  • 开局低压（教学/观察），第一个小峰用 1–3 个普通敌人；
  • 每个峰之后留一段休息（≥ 4 m 低压，最好是一个安静房间或景观点）；
  • 峰值逐渐升高，最高峰在后段（Boss / 精英房），高潮前一定有一段休息；
  • 不要从头到尾一条高平线，也不要把所有敌人堆在一个门口。

可用 meta.pacing 微调：{ "lambda": 5.5, "aggro": 8, "step": 1, "weights": { "melee": 1, "elite": 3, "boss": 6 } }（weights 的键是 enemyType）。

5. 多层地图

  • 每层一个 floors[] 项，elevation 可为负（地下）；同一层的房间不重叠，不同层可以上下重叠。
  • 楼梯：stairs[] 的 points 是矩形占地；fromFloorId/toFloorId 是两端楼层；bottom 写低端在哪一侧（N/S/E/W，N = z 大的一侧，E = x 大的一侧）。不写时 3D 只能推测朝向。
  • 楼梯占地要落在两端楼层都有房间的位置（起点层的房间里，并对着目标层的房间）。
  • 跨层路线：路线的 floorId 写出发层，经过楼梯的点写成 [x, z, y]：楼梯低端点用低层标高，高端点用高层标高，之后在新楼层上的点都带 y。
  • 敌人、门、物件都按所在楼层写 floorId，敌人必须在同层房间里。

6. 3D 怎么显示（写对字段，3D 才像样）

  • 墙：沿每个房间的边自动生成，高约 0.8×层高（上限 2.4 m）。露天庭院、广场、中庭写 "wallHeight": 0，就不会被围墙；需要矮墙/高墙时写具体米数。
  • 门：落在墙上的门会自动开洞——门不在边上，墙上就没有洞。
  • 物件高度：写 height 最准；不写时按 kind 估算（如 column/pier 3 m、altar 1.1 m、case/display 1 m、bench 0.45 m、sign 1.8 m，其他 0.8 m），且不超过层高。
  • 特殊物件 kind：floor-finish/floor-inlay = 贴地铺装（不挡路）；combat-space = 战斗留白虚线框；loot = 资源点；interaction = 交互点；extract = 撤离点（搜打撤地图请用它标每个出口，工作台的“撤离距离”图层据此计算到最近出口的步行距离；也可用 kind: "exit" 的路线终点）。
  • 颜色 color 用 #rrggbb；不写就用默认色。

code 意思 怎么改
floors-order 楼层没按标高从低到高 调整 floors[] 顺序
room-small 房间面积 < 0.5 m² 多半是点写错；删掉或放大

route-clearance 路线离某个 solid 物件不足玩家半径 折线绕开物件（推荐 ≥ 1 m），或挪物件

8. 设计质量清单（校验器查不出，但评审会看）

  • [ ] 主线完整：从入口到终点连续，每次换房间都穿过门；不穿墙、不穿实心物件。
  • [ ] 每个房间有职责：写 beat（这里发生什么）或 role；没有“只是为了凑面积”的空房。
  • [ ] 先教后考：第一场战斗简单、空间宽；新敌人类型先单独出现，再混编。
  • [ ] 锯齿节奏：压力有起伏，峰后有休息，最高峰在后段，Boss 前有喘息。
  • [ ] 可选内容有回报：每条 optional/secret 路线终点有资源、精英或捷径，并在 note 里写明。
  • [ ] 没有意外的死胡同：每个房间至少一扇门；单入口房间要有存在理由（宝箱、密室）。
  • [ ] 能撤离（有出口的地图）：撤离点用 kind: "extract" 标出；工作台“撤离距离”图层里不应有灰色（到不了出口）的可走区域，跨层靠 stairs[] 连通。
  • [ ] 敌人位置合理：不贴墙、不堵门口正中、不在楼梯上；精英/Boss 房有活动空间（≥ 8 m 短边）。
  • [ ] 引导：主线方向上有地标（大物件、亮色房间、开阔视野），不靠墙硬挡。
  • [ ] 意图写清楚：meta.designNotes 2–5 条，说明结构、节奏、关键取舍；需要人确认的事写进 reviewNotes。
  • [ ] 数字干净：坐标用整数或 .5；门宽与线段长一致；ID 语义化（r_entry、d_court、e_boss）。

9. AI 最常犯的错

  1. 方向反了：把 z 当成向下（南）。记住：z 越大越北，图上越靠上。
  2. 门画在房间中间或只碰到一个房间：门必须在两个房间共用的那条边上。
  3. 房间互相压盖：为了做 L 形把两个矩形叠在一起 → 改成共边相接。
  4. 敌人在墙上/房间外：center 恰好落在边上时判定不稳定（可能被判为房间外），一律往里挪 ≥ 1 m。
  5. 路线穿过家具：主线画直线穿过祭台、展柜 → 加折点绕开。
  6. ID 重复：楼层 1F 和房间 1F 也算重复。
  7. 输出带了 Markdown 代码块或说明文字：工作台会解析失败。
  8. 坐标超出 bounds：最后加的物件/路线点常常越界。
  9. 多层地图忘了楼梯或标高：跨层却没有 stairs[]，路线点也没写 y。

10. 交付与迭代

  1. 输出 JSON，保存为 my-map.json。
  2. 校验（能运行命令时）：python tools/validate_ai_map.py my-map.json；每条问题都带 [code]，按第 7 节修。
  3. 在工作台导入：右上“导入 JSON”，或左侧“粘贴 AI 输出的 JSON”。左侧“校验”面板列出全部问题，点一条即定位；打开“问题标记”“通行宽度”图层看哪里出问题；切 3D 看墙、门洞、楼梯朝向是否合理。
  4. 有问题时，把校验输出原样交回 AI，只改出问题的部分，ID 保持不变。
  5. 评审意见：工作台的“批注”工具会导出带 reviewNotes 的地图 JSON（targetId 指对象，at: [x, z] 指位置）。收到这样的文件时，逐条处理 status: "open" 的批注，改完把该条 status 设为 "resolved"，其余内容与 ID 不变。
